**Подробное описание логики сайта (Django-проект "godsait")**

Проект "godsait" представляет собой многофункциональную веб-платформу, разработанную на фреймворке Django, которая, судя по структуре и содержимому файлов, функционирует как онлайн-казино или игровая платформа. Архитектура проекта разделена на несколько приложений Django, каждое из которых отвечает за определенный аспект функциональности, обеспечивая модульность и удобство поддержки.

**1. Приложение `accounts` (Управление аккаунтами пользователей)**

Это приложение является ядром системы аутентификации и управления пользователями.

*   **`accounts/__init__.py`**: Стандартный файл инициализации пакета Python. Он пуст, но его наличие указывает на то, что `accounts` является пакетом, который может содержать модули.
*   **`accounts/admin.py`**: Этот файл отвечает за интеграцию пользовательской модели `CustomUser` с административной панелью Django. Строка `admin.site.register(CustomUser)` регистрирует модель, позволяя администраторам просматривать, создавать, редактировать и удалять учетные записи пользователей через удобный веб-интерфейс Django Admin. Это критически важно для управления пользователями и их балансами.
*   **`accounts/apps.py`**: Содержит конфигурацию приложения `accounts`. Класс `AccountsConfig` определяет имя приложения (`'accounts'`) и указывает `default_auto_field = 'django.db.models.BigAutoField'`, что является стандартной практикой для автоматического создания первичных ключей в моделях.
*   **`accounts/forms.py`**: В этом файле определена форма `RegisterForm`, которая используется для регистрации новых пользователей. Она наследуется от встроенной в Django `UserCreationForm`, что упрощает создание формы регистрации с базовыми полями пользователя. Дополнительно, `RegisterForm` включает поля `email` (для адреса электронной почты) и `phone` (для номера телефона), которые связаны с моделью `CustomUser`. Мета-класс `Meta` указывает, что форма работает с моделью `CustomUser` и использует поля `username`, `email`, `phone`.
*   **`accounts/models.py`**: Это один из наиболее важных файлов, так как он определяет модель `CustomUser`, которая расширяет стандартную `AbstractUser` Django. Это позволяет добавлять пользовательские поля к стандартной модели пользователя. Ключевые поля включают:
    *   `balance`: `DecimalField` для хранения основного баланса пользователя, с начальным значением `1000.0`.
    *   `blinko_balance`, `blingo_balance`: Дополнительные `DecimalField` для хранения балансов, специфичных для игр Blinko и Blingo соответственно, также с начальным значением `1000.0`. Это позволяет изолировать балансы для разных игр или предоставлять стартовый капитал для них.
    *   `phone`: `CharField` для номера телефона пользователя, может быть пустым (`blank=True`).
    *   `blinko_plays_today`, `blingo_plays_today`: `IntegerField` для отслеживания количества игр Blinko и Blingo, сыгранных за текущий день, с начальным значением `0`.
    *   `last_blinko_play_date`, `last_blingo_play_date`: `DateField` для хранения даты последней игры Blinko и Blingo. Эти поля используются для реализации ежедневного сброса попыток или балансов.
    *   Метод `__str__` возвращает имя пользователя, что удобно для отображения в административной панели и логах.
*   **`accounts/tests.py`**: Файл предназначен для написания модульных и интеграционных тестов для приложения `accounts`. В текущем состоянии он пуст, что указывает на отсутствие реализованных тестов.
*   **`accounts/urls.py`**: Определяет маршруты URL для функций, связанных с управлением аккаунтами:
    *   `path('register/', views.register, name='register')`: URL для страницы регистрации.
    *   `path('login/', CustomLoginView.as_view(), name='login')`: URL для страницы входа, использующий класс-представление `CustomLoginView`.
    *   `path('logout/', views.logout_view, name='logout')`: URL для выхода из системы.
    *   `path('get_balance/', views.get_user_balance, name='get_user_balance')`: URL для AJAX-запросов, позволяющих получить текущий баланс пользователя.
*   **`accounts/views.py`**: Содержит логику обработки запросов, связанных с аккаунтами:
    *   `register(request)`: Функция-представление для регистрации. Обрабатывает POST-запросы с данными формы регистрации. Если форма валидна, создает нового пользователя, автоматически входит его в систему (`login(request, user)`) и перенаправляет на главную страницу (`index`). Для GET-запросов отображает пустую форму регистрации.
    *   `CustomLoginView(LoginView)`: Класс-представление, расширяющее стандартный `LoginView`. Он использует шаблон `accounts/login.html`. Метод `form_valid` переопределен для сохранения дополнительной информации о пользователе (`username`, `user_id`, `balance`) в сессии после успешной аутентификации. Это позволяет быстро получать доступ к этим данным на клиентской стороне без дополнительных запросов к базе данных.
    *   `logout_view(request)`: Функция-представление, которая выполняет выход пользователя из системы (`logout(request)`) и перенаправляет его на главную страницу.
    *   `get_user_balance(request)`: AJAX-представление, защищенное декоратором `@login_required`. Если пользователь аутентифицирован, возвращает его текущий баланс в формате JSON. В противном случае возвращает `0.0`.

**2. Приложение `game` (Игры)**

Это приложение содержит логику и шаблоны для различных игр, представленных на платформе.

*   **`game/__init__.py`**: Стандартный файл инициализации пакета Python. Пуст.
*   **`game/admin.py`**: Файл для регистрации моделей приложения `game` в административной панели Django. В текущем состоянии пуст, но может быть использован для регистрации `GameAttempt` или других моделей, связанных с играми.
*   **`game/apps.py`**: Конфигурация приложения `game`. Класс `GameConfig` определяет имя приложения (`'game'`) и тип поля `default_auto_field`.
*   **`game/models.py`**: Определяет модель `GameAttempt`, которая используется для логирования каждой попытки пользователя в игре. Поля включают:
    *   `user`: `ForeignKey` к модели `CustomUser`, указывающий, какой пользователь совершил попытку. Может быть `null` и `blank`, если попытка совершена неаутентифицированным пользователем (хотя большинство игровых функций требуют аутентификации).
    *   `game_name`: `CharField` для хранения названия игры (например, 'blingo', 'blinko', 'roulette').
    *   `timestamp`: `DateTimeField` с `auto_now_add=True` для автоматической записи времени попытки.
    *   `attempts_count`: `IntegerField` для подсчета попыток (по умолчанию `0`).
    *   `game_score`: `IntegerField` для хранения счета или выигрыша в данной попытке (по умолчанию `0`).
    *   `result`: `CharField` для записи результата игры ('win'/'lose' или 'unknown').
    *   Мета-класс `Meta` определяет читаемые имена для модели (`verbose_name`, `verbose_name_plural`) и порядок сортировки по `timestamp`.
*   **`game/tests.py`**: Файл для написания тестов приложения `game`. В текущем состоянии пуст.
*   **`game/urls.py`**: Определяет URL-адреса для всех игровых страниц и связанных с ними API-эндпоинтов:
    *   `path('case/silver/', views.case_silver, name='case_silver')`, `path('case/bronze/', views.case_bronze, name='case_bronze')`, `path('case/gold/', views.case_gold, name='case_gold')`: URL-ы для различных "кейсовых" игр.
    *   `path('craps/', views.craps, name='craps')`, `path('fortune/', views.fortune, name='fortune')`, `path('punto-banco/', views.punto_banco, name='punto_banco')`, `path('blackjack/', views.Blackjack, name='Blackjack')`, `path('roulette/', views.roulette, name='roulette')`: URL-ы для классических казино-игр.
    *   `path('blingo/', views.blingo, name='blingo')`: URL для игры Blingo (поиск чисел).
    *   `path('blinko/', views.blinko, name='blinko')`: URL для игры Blinko (Plinko).
    *   `path('update_redirect/', views.update_redirect, name='update_redirect')`: Универсальный URL для обновления баланса после игры и перенаправления.
    *   **URL-ы для Blingo (поиск чисел):**
        *   `path('check_blingo_attempts/', views.check_blingo_attempts, name='check_blingo_attempts')`: Проверка оставшихся попыток.
        *   `path('blingo/save-attempt/', views.save_game_attempt, name='save_attempt')`: Сохранение результатов попытки.
        *   `path('start-blingo-play/', views.start_blingo_play, name='start_blingo_play')`: Начало новой игры Blingo.
    *   **URL-ы для Blinko (Plinko):**
        *   `path('save-blinko-score/', views.save_blinko_score, name='save_blinko_score')`: Сохранение счета Blinko.
        *   `path('reset-blinko/', views.reset_blinko_attempts, name='reset_blinko_attempts')`: Сброс ежедневных попыток Blinko.
    *   `path('update_roulette_balance/', views.update_roulette_balance, name='update_roulette_balance')`: Обновление баланса после игры в рулетку.
*   **`game/views.py`**: Содержит основную логику для обработки игровых процессов:
    *   `case_silver`, `case_bronze`, `case_gold`, `craps`, `fortune`, `punto_banco`, `Blackjack`, `roulette`: Эти функции-представления являются простыми рендерами соответствующих HTML-шаблонов игр. Они служат точками входа для отображения игрового интерфейса. Для Blackjack и Roulette, создание записи `GameClick` (для отслеживания баланса до игры) делегируется функции `track_game_click` из приложения `pages`.
    *   `blingo(request)`: Представление для игры Blingo. Если пользователь аутентифицирован, оно реализует логику ежедневного сброса `blingo_balance` и `blingo_plays_today` при первом посещении за день. Также создает запись `GameClick` для отслеживания баланса до начала игры.
    *   `blinko(request)`: Представление для игры Blinko (Plinko). Требует аутентификации. Реализует логику ежедневного сброса `blinko_plays_today` и проверку на максимальное количество попыток (3 в день). При каждом посещении страницы увеличивает счетчик `blinko_plays_today`. Создает запись `GameClick` для отслеживания баланса.
    *   `start_blingo_play(request)`: AJAX-представление (декораторы `@csrf_exempt`, `@login_required`) для начала игры Blingo. Проверяет и увеличивает счетчик `blingo_plays_today`, возвращая статус успеха или неудачи.
    *   `check_blingo_attempts(request)`: AJAX-представление (декоратор `@login_required`) для проверки оставшихся попыток в Blingo. Возвращает информацию о возможности играть и количестве попыток.
    *   `save_game_attempt(request)`: AJAX-представление (декораторы `@csrf_exempt`, `@login_required`) для сохранения результатов игры Blingo. Принимает счет игры, добавляет выигрыш к основному балансу пользователя (`request.user.balance`), сохраняет пользователя и создает запись `GameAttempt`.
    *   `save_blinko_score(request)`: AJAX-представление (декораторы `@csrf_exempt`, `@login_required`) для сохранения результатов игры Blinko (Plinko). Обновляет основной баланс пользователя, сессию и соответствующую запись `GameClick` (если она была создана).
    *   `update_redirect(request)`: Универсальное AJAX-представление (декоратор `@login_required`) для обновления баланса пользователя после завершения игры и последующего перенаправления. Оно извлекает `game_click_id` из сессии, находит соответствующую запись `GameClick`, обновляет `new_balance` и основной баланс пользователя, а также удаляет временные данные из сессии.
    *   `reset_blinko_attempts(request)`: Функция-представление (декоратор `@login_required`) для сброса ежедневных попыток игры Blinko.
    *   `update_roulette_balance(request)`: AJAX-представление (декораторы `@csrf_exempt`, `@login_required`) для обновления баланса пользователя после игры в рулетку. Обновляет основной баланс пользователя и сессию.

**3. Приложение `pages` (Основные страницы)**

Это приложение управляет общими статическими страницами сайта и механизмами отслеживания.

*   **`pages/__init__.py`**: Стандартный файл инициализации пакета Python. Пуст.
*   **`pages/admin.py`**: Файл для регистрации моделей приложения `pages` в административной панели Django. В текущем состоянии пуст, но может быть использован для регистрации `GameClick`.
*   **`pages/apps.py`**: Конфигурация приложения `pages`. Класс `PagesConfig` определяет имя приложения (`'pages'`) и тип поля `default_auto_field`.
*   **`pages/models.py`**: Определяет модель `GameClick`, которая играет ключевую роль в отслеживании активности пользователя. Поля включают:
    *   `user`: `ForeignKey` к `CustomUser`, может быть `null` для неаутентифицированных пользователей.
    *   `game_name`: Название игры, на которую был сделан клик.
    *   `target_url`: URL страницы игры.
    *   `timestamp`: Время клика.
    *   `current_balance`: Баланс пользователя до клика.
    *   `new_balance`: Баланс пользователя после завершения игры (обновляется позже).
    *   `total`: Разница между `new_balance` и `current_balance`, вычисляется автоматически в методе `save`.
    *   Метод `save` переопределен для автоматического вычисления поля `total` перед сохранением объекта, что позволяет отслеживать выигрыш или проигрыш в каждой сессии игры.
*   **`pages/tests.py`**: Файл для написания тестов приложения `pages`. В текущем состоянии пуст.
*   **`pages/urls.py`**: Определяет URL-адреса для основных страниц и функции отслеживания:
    *   `path('', views.home_page, name='index')`: Главная страница сайта.
    *   `path('about/', views.about_page, name='about')`: Страница "О нас".
    *   `path('track-click/', views.track_game_click, name='track-game-click')`: URL для POST-запросов, используемых для отслеживания кликов по играм.
*   **`pages/views.py`**: Содержит логику для отображения статических страниц и отслеживания:
    *   `home_page(request)`: Рендерит шаблон `pages/index.html` (главная страница).
    *   `about_page(request)`: Рендерит шаблон `pages/about.html` (страница "О нас").
    *   `track_game_click(request)`: Функция-представление (декоратор `@csrf_protect`) для обработки POST-запросов, отправляемых при переходе пользователя на страницу игры. Она создает новую запись `GameClick`, фиксируя `game_name`, `target_url` и `current_balance` пользователя (из сессии). `id` созданной записи сохраняется в сессии (`last_game_click_id`), чтобы позже можно было обновить `new_balance` после завершения игры. Затем пользователь перенаправляется на `target_url`.

**4. Приложение `profil` (Профиль пользователя)**

Это приложение отвечает за отображение информации о профиле пользователя и его игровой статистике.

*   **`profil/__init__.py`**: Стандартный файл инициализации пакета Python. Пуст.
*   **`profil/admin.py`**: Файл для регистрации моделей приложения `profil` в административной панели Django. В текущем состоянии пуст.
*   **`profil/apps.py`**: Конфигурация приложения `profil`. Класс `ProfilConfig` определяет имя приложения (`'profil'`) и тип поля `default_auto_field`.
*   **`profil/models.py`**: Файл для определения моделей приложения `profil`. В текущем состоянии пуст, что означает, что вся необходимая информация для профиля берется из `accounts.CustomUser` и `pages.GameClick`.
*   **`profil/urls.py`**: Определяет URL-адрес для страницы профиля:
    *   `path('', views.prof, name='prof')`: URL для отображения профиля пользователя.
*   **`profil/views.py`**:
    *   `prof(request)`: Функция-представление (декоратор `@login_required`) для страницы профиля. Она извлекает из базы данных последние 20 записей `GameClick` для текущего пользователя, рассчитывает общую статистику (общее количество игр, любимая игра на основе количества кликов, последняя активность). Все эти данные передаются в контекст шаблона `profil/prof.html` для отображения.

**5. Основной проект `godsait`**

Это корневой каталог Django-проекта, содержащий глобальные настройки и конфигурации.

*   **`godsait/__init__.py`**: Стандартный файл инициализации пакета Python. Пуст.
*   **`godsait/asgi.py`**: Конфигурация для ASGI (Asynchronous Server Gateway Interface). Используется для развертывания проекта с асинхронными веб-серверами (например, Daphne, Uvicorn), что позволяет обрабатывать веб-сокеты и другие асинхронные операции.
*   **`godsait/settings.py`**: Главный файл конфигурации Django-проекта. Он содержит множество настроек, определяющих поведение всего сайта:
    *   `BASE_DIR`: Определяет корневой каталог проекта.
    *   `SECRET_KEY`: Уникальный секретный ключ, используемый для криптографической подписи Django.
    *   `DEBUG`: Булево значение, указывающее, включен ли режим отладки. В режиме `DEBUG = True` отображаются подробные ошибки, что удобно для разработки.
    *   `ALLOWED_HOSTS`: Список доменных имен, которые может обслуживать этот Django-сайт.
    *   `INSTALLED_APPS`: Список всех установленных приложений Django, включая встроенные (`django.contrib.*`) и пользовательские (`pages`, `accounts`, `game`, `profil`, `rest_framework`, `rest_framework.authtoken`).
    *   `MIDDLEWARE`: Список промежуточного ПО, которое обрабатывает запросы и ответы на разных этапах.
    *   `ROOT_URLCONF`: Указывает на главный файл URL-адресов проекта (`godsait.urls`).
    *   `TEMPLATES`: Конфигурация системы шаблонов Django, включая пути к шаблонам и контекстные процессоры.
    *   `WSGI_APPLICATION`: Указывает на WSGI-приложение проекта (`godsait.wsgi.application`), используемое для синхронных веб-серверов (например, Gunicorn, Apache с mod_wsgi).
    *   `DATABASES`: Настройки базы данных. В данном случае используется SQLite3 (`db.sqlite3`).
    *   `AUTH_PASSWORD_VALIDATORS`: Настройки валидаторов паролей для повышения безопасности.
    *   `AUTH_USER_MODEL`: Важная настройка, указывающая, что в качестве пользовательской модели используется `accounts.CustomUser`.
    *   `LOGIN_REDIRECT_URL`, `LOGOUT_REDIRECT_URL`: URL-ы, на которые пользователь будет перенаправлен после успешного входа и выхода соответственно.
    *   `LANGUAGE_CODE`, `TIME_ZONE`, `USE_I18N`, `USE_TZ`: Настройки интернационализации, часового пояса и поддержки временных зон.
    *   `APPEND_SLASH`: Автоматически добавляет слэш к URL-ам, если его нет.
    *   `STATIC_URL`, `STATIC_ROOT`, `STATICFILES_DIRS`: Настройки для обслуживания статических файлов (CSS, JavaScript, изображения). `STATICFILES_DIRS` указывает, где Django должен искать статические файлы приложений.
    *   `DEFAULT_AUTO_FIELD`: Тип поля для автоматического первичного ключа.
*   **`godsait/urls.py`**: Главный файл URL-адресов проекта. Он включает URL-адреса из всех пользовательских приложений (`pages`, `accounts`, `game`, `profil`) с помощью функции `include()`, а также URL для административной панели Django (`admin/`).
*   **`godsait/wsgi.py`**: Конфигурация для WSGI (Web Server Gateway Interface). Используется для развертывания проекта с синхронными веб-серверами.

**6. `manage.py`**

*   Это стандартная утилита командной строки Django. Она используется для выполнения различных административных задач, таких как запуск сервера разработки (`runserver`), создание миграций базы данных (`makemigrations`), применение миграций (`migrate`), создание суперпользователя (`createsuperuser`) и многих других.

**7. `gameNew/` (Временные/тестовые файлы игр)**

*   Эта директория содержит поддиректории (`Case`, `Craps`, `Fortune`, `Punto Banco`) с файлами `main.py`. Судя по тому, что их содержимое не было возвращено при чтении (вероятно, они пустые или содержат только тестовый код), эти файлы, скорее всего, являются отдельными скриптами или прототипами игр, которые не интегрированы напрямую в основной Django-проект. Они могут использоваться для локальной разработки или тестирования отдельных игровых механик вне контекста Django.

**Общая логика взаимодействия и потоки данных:**

1.  **Аутентификация и сессии:** Пользователи регистрируются и входят через приложение `accounts`. После успешного входа, их основные данные (username, user_id, balance) сохраняются в сессии Django (`request.session`), что обеспечивает быстрый доступ к ним на протяжении всей сессии пользователя.
2.  **Навигация и отслеживание:** При переходе на любую игровую страницу, клиентский JavaScript (или напрямую Django-представление) отправляет POST-запрос на `pages/views.py:track_game_click`. Эта функция создает запись `GameClick` в базе данных, фиксируя имя игры, целевой URL и текущий баланс пользователя. `id` этой записи сохраняется в сессии.
3.  **Игровой процесс:** Каждая игра в приложении `game` имеет свое представление (`game/views.py`) и соответствующие статические файлы (JS/CSS) для клиентской логики. В зависимости от игры, могут быть реализованы специфические механизмы сброса ежедневных попыток или балансов (например, для Blingo и Blinko).
4.  **Обновление баланса и результатов:** После завершения игры (например, через AJAX-запросы к `game/views.py:save_game_attempt`, `save_blinko_score`, `update_roulette_balance` или `update_redirect`), основной баланс пользователя в модели `CustomUser` обновляется. Также обновляется `new_balance` в соответствующей записи `GameClick`, и поле `total` автоматически пересчитывается, отражая выигрыш или проигрыш. Баланс в сессии также обновляется, чтобы клиентская сторона всегда имела актуальные данные.
5.  **Профиль пользователя:** Приложение `profil` агрегирует данные из `GameClick` для отображения истории игр, общей статистики и любимых игр пользователя на его странице профиля.
6.  **Статические файлы:** Все CSS, JavaScript и изображения, необходимые для оформления и интерактивности сайта, обслуживаются через систему статических файлов Django, настроенную в `godsait/settings.py`.
7.  **База данных:** SQLite3 (`db.sqlite3`) используется для хранения всех данных: пользовательских аккаунтов, истории игр, балансов и другой информации. Миграции Django управляют структурой базы данных.

Проект демонстрирует типичную структуру Django-приложения с четким разделением ответственности между приложениями, использованием моделей для хранения данных, представлений для обработки логики и шаблонов для отображения пользовательского интерфейса. Использование сессий и AJAX-запросов обеспечивает динамичное взаимодействие с пользователем и обновление данных в реальном времени.
